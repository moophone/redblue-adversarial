# 接入卡：在其他会话里使用红蓝对抗

## 先分清一件事

这套机制是**文件契约**，不是后台服务。它不会"运行"，只有被某个会话读进来并照着做才生效。
所以真正要解决的不是"怎么连上它"，而是两件事：

1. 怎么让那个会话知道它存在；
2. 怎么让多个会话不抢同一份状态。

## 三种接法

### A. 让另一个会话当红队（只读，最常用）

```
读 D:\1a个人\科研\_redblue\README.md、protocol.md、roles/red.md。
按红队身份对 <交付件绝对路径> 跑一轮评审，产出
rounds/<轮次>-<会话短码>/01-cases.md 和 03-review.md。
不改交付件。每条问题给「位置 + 原因 + 修正方向」，无证据的条目不要写。
```

红队只读不写交付件，所以**只读权限的会话也能干红队**——这是让那两个 session 参与的最低成本方式。

### B. 让另一个会话当蓝队（执行 + 自证）

```
读 D:\1a个人\科研\_redblue\protocol.md、roles/blue.md。
先读 rounds/<轮次>-<会话短码>/01-cases.md（没有就先不接红队用例），
再对 <任务> 执行，产出 02-blue.md，每条用例给「已修 / 不成立+反证 / 挂账」。
改稿只另存新版本，不动原件。
```

### C. 常驻（如果该会话支持项目级指令）

把这段放进该工作区的项目指令文件里（该会话若不支持常驻指令，就只能每次手动粘 A/B）：

```
本项目有红蓝对抗机制在 _redblue/ 下。涉及交付件评审时，先读 _redblue/protocol.md。
红蓝两方不可由同一会话兼任。
```

## 最关键的一条：分工，不是复制

对抗的价值来自**审查者和作者不是同一个上下文**。同一个会话自己审自己，
它清楚自己刚才为什么那么写，会把偏差读成"有理由的"，评审就退化成自我背书。

所以那两个 session 的正确用法不是"各自也跑一套红蓝"，而是：

- 它们各当**蓝队**，干自己的科研任务，把交付件路径登记进 `state.md`；
- **红队放到第三个会话**（或放到本会话），只读它们的产出。

## 并发会打架的三处

| 位置 | 冲突 | 约定 |
| --- | --- | --- |
| 轮次目录 | 同名互撞 | 目录名带会话短码：`R1-88d6`、`R1-8a0c` |
| `state.md` | 同时写会覆盖 | 只追加行，不重写全文 |
| 同一个交付件 | 两个蓝队同时改 | 禁止；换人先在 `state.md` 改归属 |

短码取 session id 前 4 位，够用且不用记全。

## 跨工作区怎么办

那两个 session 若工作目录不是 `D:\1a个人\科研`，可能读不到这里的 `_redblue`。两种处理：

- **各存一份**：把 `_redblue` 整个复制到那个工作区根下，两边状态独立、互不干扰；
- **单侧集中**：交付件路径写进同一侧的 `state.md`，让能读到全部文件的那一侧（本会话）跑红队。

不要跨两个工作区共享同一个 `state.md`——文件不互通，共享等于各说各话。

## 轮次目录命名

```
rounds/R1-88d6/     ← 轮次 1，会话 88d61362… 跑的
rounds/R1-8a0c/     ← 轮次 1，会话 8a0c416f… 跑的
```

同一轮同一会话内仍是标准四件：`01-cases.md`、`02-blue.md`、`03-review.md`、`04-summary.md`。
