# 请评估：问题清单

> 这是三份送审文件的第三份。`01` 是完整设计（自包含），`02` 是实测记录与已知问题。
> 本文件只做一件事：**把要你判断的问题问清楚**。

## 0. 怎么用

1. 先读 `01`（设计正本，含平台事实）和 `02`（2 次实跑的原始数据）
2. 逐条回答下面 10 个问题
3. 每条按这个格式：**结论 → 依据 → 可操作建议**
4. 把「事实」「判断」「不确定」分开写
5. **不要复述设计**，直接回答
6. 如果你发现设计里有事实错误，直接指出，并给证据

---

## 1. 背景（一句话）

一套"红队攻击 / 蓝队修正 / 主控判闸门"的评审机制，用**一个对话 + 多个子代理**实现，用来对科研交付件（论文、数据分析、代码）做交付前把关。已经在真实交付件上跑过 2 次。

**用户的硬约束**（不能违背）：

- **必须在一个对话里跑完**（不要建议"另开会话当红队"）
- **运行中不向用户提问**（自动化；只在"审哪个"这种无法推断时问一次）
- 场景是**做实事的科研**，不是演示

**平台限制**（不要建议做不到的）：

- 子代理有两种：`subagent`（全新上下文）/ `subagent_fork`（继承父对话）
- 沙箱是**按会话**算的，不能给单个子代理设只读
- 对话内**不支持 Mermaid、不支持原始 HTML**；支持表格、本地图片、KaTeX
- 有一个 Agent Teams 的 UI（header 弹层：roster + 共享任务板）
- 有可扩展的右侧边栏（公开 API，但状态只在内存、刷新丢失）

**不要讨论"换个更强的模型"**——用户明确说了不谈模型能力，只谈架构。

## 2. 要你回答的 10 个问题

### Q1 独立性怎么补

现在的独立性是"弱独立"：主控把目标、验收标准、红队用例都喂给下一方，世界观由同一个模型、同一个主控框定。

候选手段（我已经想到的）：

- **跨模型**：红队换成另一个 provider
- **零上下文派工**：不给红队验收标准，只给交付件，让它自己抽"它声称了什么"
- **红队不写文件**：只返回文本，主控落盘

请评估这三个的**实际增益排序**，并补充我没想到的。

### Q2 红队不写文件，是否可行

让红队只返回文本、主控落盘，能**物理上**杜绝"红队改交付件"（现在只靠事后指纹，分不清谁改的）。

但代价是什么？会不会破坏"红队独立署名 / 可追溯"？有没有比这更好的隔离办法？

### Q3 闸门要不要加"覆盖度"

现在闸门只有一维：致命 = 0 且 严重 = 0。

红队只造 20 条用例，如果它**漏掉一整类问题**（伦理、统计前提、合规），闸门照样放行。

要不要加"红队必须申报覆盖了哪些维度 / 哪些没覆盖"？**怎么防止红队虚报覆盖**？

### Q4 "可复算覆盖率"当硬准入，会不会误伤

想把"每条致命/严重必须绑定一个可执行验证"变成硬准入（跑不出结果的不许立致命/严重）。

但这会不会把**只能靠判断、无法跑**的真问题排除掉（比如论证逻辑断裂、伦理问题、写作质量）？

如果会，怎么划这条线？

### Q5 红队自己漏判，谁来补

红队把**致命漏判成一般**，现在没有任何机制能发现（只有它误判成致命时，蓝队能反驳）。

有什么低成本的办法校准红队？双向盲审？红蓝互换？第三方抽检？

### Q6 串行能不能并行

一轮是 红 → 蓝 → 红，严格串行，约 40 分钟。

红队用例**按维度**拆成 3 个并行子代理，会不会各自漏掉**跨维度**的问题？值不值得？

还有哪些环节可以安全并行？

### Q7 插件还是 skill，边界在哪

现在 90% 是 skill（模型执行协议文本），只有少量脚本。

哪些部分**必须**下沉到插件/工具（确定性执行），哪些**应该**留在 skill（需要判断）？请给判定标准，而不是清单。

### Q8 可视化怎么排优先级

三个候选：

| 方案 | 位置 | 开发量 |
| --- | --- | --- |
| A. Agent Teams 任务板 | header 弹层（roster + 每条用例一个任务） | 0 |
| B. 右侧边栏专用看板 | 真侧边栏 | 大（host RPC + client 组件） |
| C. 对话内状态行 + 三方对照表 | 对话流里 | 0 |

请按**对结论质量的实际贡献**排序，**不要按"看起来爽"**。并说明理由。

### Q9 这套机制的定位

它到底是"**多轮评审流程**"，还是"**证据收集流程**"？

如果只能保留一个机制（多轮迭代 或者 强制可复算），该保留哪个？为什么？

### Q10 最狠的一问

如果你认为这套架构的**根本方向就是错的**，请直接说，并给出替代方案。不要为了礼貌而保留。
