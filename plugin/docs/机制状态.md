- 2026-11-01（课题16 R6/R7 教训）：
  6. **「不可复现」的指控必须先试遍口径**。R7 技术审查员 T01 判「5.4651/0.207414/n=325 不可复现」，实测是**窗口闭/半开定义差 1 个采样点**（闭 `≤360` 跨度恰 360 s → n=325、5.465132；半开 `<360` → n=324、5.469453）。**两口径都真，差 0.079%**。⇒ 凡报「最坏值」必须同时给窗口定义；凡判「不可复现」必须先复现对方的口径。
  7. **`bundle` 的文件名正则是 ASCII `[\w.\-]`，中文文件名会被截断**。`E1_瞬时vs6minRMS.py:64-66` 在 JS 里被截成 `vs6minRMS.py:64-66` ⇒ 报 MISSING 且无法修复。**修法：把被引文件复制一份 ASCII 名到轮次目录**（如 `E1_powerratio.py`、`GB8702_extracted.txt`），引用改成 ASCII 名。
  8. **`bundle`/`lineCount` 按 UTF-8 读文件**。UTF-16 保存的输出（`E1_out.txt` 实测）会被读成 0 行 ⇒ `OUT_OF_RANGE … 文件只有 0 行 ([object Object])`。**修法：转成 UTF-8。** 另：`([object Object])` 表示 `findFile` 返回了歧义对象（同名文件多份）⇒ 复制一份到轮次目录消除歧义。
  9. **`audit` 是 `bundle` 的超集**，必须先过 `bundle` 再跑 `audit`，否则 `AUDIT: ROUND INVALID`。
  10. **红队子代理会空跑**。R6 `dd5fabb7`（42 次 compaction / 全程只写 17 行骨架）、R7 `20d38a46`（22 分钟只写 3 行骨架 / 会话涨到 571 KB）。根因是**任务给法**：把 1.9 MB 台账当输入 ⇒ 上下文被压缩反复清空 ⇒ 重读大文件 ⇒ 攒着不落盘。**修法：persona 内禁止写骨架、要求单次 write 交付完整表；只给行号区间，不给整份大文件。**
